# TechFix REST API

Base URL: `http://localhost:8000/api`. Send `Accept: application/json`, `Content-Type: application/json` and, for protected endpoints, `Authorization: Bearer <token>`.

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/register` | `name`, `email`, `password`, `password_confirmation`; employee account |
| POST | `/login` | `email`, `password`; returns `{user, token}` |
| POST | `/logout` | Revoke the current token |
| GET, PUT | `/profile` | Read/update own `name` and `email` |
| GET | `/dashboard` | Customer, device, open order, completed order counts |
| GET | `/employees` | Minimal staff IDs/names for assignment selectors |
| GET, POST | `/{resource}` | List/create records |
| GET, PUT, DELETE | `/{resource}/{id}` | Read/update/delete a record |

Resources: `clientes`, `aparelhos`, `ordens-servico`, `parts`, `users`. Every endpoint except login/register requires authentication. `users` requires the administrator role for every operation. All other resources are available to staff. Tokens expire after 30 days. Authentication is limited to 10 requests/minute per IP; protected endpoints to 120/minute.

## Request fields

- **clientes:** `name`, `phone` required; `email`, `address` optional.
- **aparelhos:** `brand`, `model` required; `cliente_id` optional/nullable (must reference an existing customer when provided), `notes` optional. Send `cliente_id: null` to unlink a customer. Legacy `imei` remains optional and unique in the API for compatibility; the app no longer offers IMEI entry.
- **ordens-servico:** `aparelho_id`, `problem`, `status`, `price` required; `assigned_to`, `diagnosis`, `notes` optional. `number` and `created_by` are generated by the server and cannot be overwritten by a client.
- **parts:** `name`, unique `sku`, integer `quantity >= 0`, `price >= 0` required.
- **users:** `name`, unique `email`, `role` (`admin` or `employee`) required. `password` (8+ characters) required on creation, optional on update.

PUT submits all required fields. Send `null` to clear optional fields. Prices are JSON numbers in requests and decimal strings in responses. Quantities are integers. Both price and quantity have upper bounds enforced by validation.

List returns an array (newest first), detail/create/update return an object; creation returns HTTP 201 and deletion HTTP 204. List endpoints support `?search=text`. Repair lists additionally support `?status=completed`. This classroom implementation returns all matches without pagination.

Order statuses: `received`, `diagnosing`, `awaiting_parts`, `repairing`, `completed`, `delivered`, `cancelled`. Transitions between these statuses are unrestricted. Order responses include `aparelho.cliente`, `assigned_user`, and `history` with the staff member and timestamp for each status change. Order number generation and history writes are transactional.

Errors use JSON `{message, errors?}`: 401 unauthenticated/expired token; 403 permission denied; 404 missing resource; 409 linked records prevent deletion; 422 validation; 429 rate limit. Validation `errors` maps field names to arrays of messages. Employees cannot grant themselves administrator permissions through registration or profile updates.

## Example

```json
{
  "aparelho_id": 1,
  "assigned_to": 1,
  "problem": "Tela quebrada",
  "diagnosis": "Substituir display",
  "status": "repairing",
  "price": 250.00,
  "notes": "Cliente aprovou orçamento"
}
```
